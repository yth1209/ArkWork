# 설계 결정과 미결정 사항

## 기본안

| ID | 결정 | 근거·적용 범위 |
| --- | --- | --- |
| D-01 | 완성형 Factory를 제품 목표로 한다 | 사용자가 구성 도구보다 결과를 원하는 방향을 선택 |
| D-02 | 현재 UI 데모와 실서비스를 구분한다 | 기존 사용자 선택은 UI 우선; 실제 실행을 허위 표시하지 않음 |
| D-03 | ArkWork 개발 변경은 검증 후 main에 직접 커밋·push | 2026-10-01 사용자 지시로 기존 브랜치·PR 절차를 대체. 명시적으로 요청한 경우에만 PR을 생성한다. 제품이 대상 저장소에 생성하는 PR 흐름은 별도 제품 요구사항이다 |
| D-04 | 첫 지원 대상은 GitHub·TypeScript 웹 앱 | 현재 스택 재사용과 검증 범위를 제한하기 위한 제안 |
| D-05 | server state와 event를 작업의 기준으로 둔다 | 브라우저 타이머·localStorage만으로 영속 자동화 불가 |
| D-06 | 기존 React/Vite와 Node.js 기반 API를 유지한다 | 불필요한 UI 재작성 방지 |
| D-07 | 실행·게시·승인 권한을 분리한다 | 비신뢰 코드·코멘트로 권한이 확대되는 문제 방지 |
| D-08 | 첫 개선 루프는 review Skill, local 규칙 우선 | Warp의 범위와 피드백 일반화 위험을 반영 |
| D-09 | Skill 변경에 평가·별도 PR·버전 고정을 둔다 | 지침 회귀를 검증·복구하고 과거 결과를 추적 |
| D-10 | 외부 미리보기는 별도 배포 기능이다 | 현 클라우드 서버는 사용자 접속 링크로 전달되지 않았음 |
| D-11 | 로컬 개발은 PGlite, 외부 DB는 PostgreSQL adapter | 컨테이너 다운로드 제한을 확인. 같은 SQL·transaction 계약으로 영속 로컬 개발과 독립 테스트를 제공한다. 외부 DB 검증은 후속 작업 |
| D-12 | 현재 인증은 명시적 개발 세션으로 한정 | 사용자 신원 증명은 GitHub 인증 연결 시 제공. 로컬 개발 계정 선택을 운영 인증으로 표현하지 않는다 |
| D-13 | 모의 작업에도 계획·정책·버전 고정 승인을 적용 | 실행과 승인·취소·재시작의 연결을 실제 영속 상태로 검증. fixture 승인은 유료 AI·GitHub 쓰기 권한으로 확대하지 않는다 |
| D-14 | 초기 큐는 workspace 실행 1건, 승인 작업 3건, 자동 시도 2회 | 서버 모의 단계에서 lease·generation·한도 동작을 검증. 실패 시 새 유료 실행이나 자동 무한 재시도를 하지 않는다 |
| D-15 | 실제 AI 연결 전에 단계별 사람 개입·재개를 구현 | 사용자가 Factory의 핵심이라고 지정. 질문·결정·피드백 내용은 우선 데모 항목으로 한정하고 응답·권한·이력은 실제 영속 상태로 검증 |
| D-16 | 수정 계획에는 재승인, 결과 완료에는 사람 승인 필요 | 이전 계획 승인을 새 범위에 재사용하지 않고 대기를 자동 완료하지 않음. 변경 회차 3회, 회차별 자동 시도 2회로 제한 |
| D-17 | Codex SDK·CLI와 별도 ChatGPT 구독 로그인을 사용 | 사용자 선택. API 키 fallback과 개발 채팅 인증 재사용 없음. 로컬 owner의 명시적 질문·명세 호출부터 적용 |
| D-18 | Codex planning 호출은 자동 재호출하지 않는다 | 구독 사용량 중복 소모 방지. 2분·동시 1건·회차별 종류당 2회 제한, 취소·오래된 결과 차단 |

| D-19 | 실제 구현 브랜치를 PR로 제출하고 커밋별 사람 평가를 저장 | 사용자 요청. Codex 구현은 아직 미구현이므로 출처를 명시하고 빈 모의 결과로 PR을 만들지 않는다. 승인 전 원격 SHA·CI 확인, 변경 시 승인 해제, 내부 평가와 GitHub Review·병합을 구분 |

## 구현 전에 확정할 사항

| 항목 | 기본 가정 | 결정 시점·필요 증거 |
| --- | --- | --- |
| Agent 공급자 | Codex SDK·CLI + ChatGPT 구독, 개인용 planning pilot | 실제 로그인·호출 검증, 운영용 계정·격리 worker와 코드 실행 계약은 후속 |
| 호스팅 | API·DB·worker·객체 저장소 분리 | M1 배포 전: 계정·지역·견적·backup·네트워크 |
| GitHub App 설치 | 단일 사용자·선택 저장소 | M2: 소유자 설정, webhook domain·secret, 최소 permissions |
| 실행 예산 | 작업별 예약과 유한 재시도 | M2·M3: 공급자 단가와 pilot 실측 |
| 공개 범위 | 기본 비공개, 외부 배포는 승인 | 첫 배포 전: 인증, URL, 비용·TTL |
| 조직 정책 | 개인 프로젝트부터 | M6: 역할·감사·보관·테넌트 경계 |
| 자동 수정 실행 | 첫 MVP는 수정 계획 승인 후 | M4: 실행 권한, head SHA, 허용 범위와 예산 |
| 학습 임계값 | 2건 반복 또는 명시적 지속 규칙 | M5: 실제 feedback corpus와 회귀 평가 집합 |

미결정 항목을 임의의 자격 증명이나 무료 사용 가정으로 채우지 않는다. 해당 항목에 의존하지 않는 개발은 fixture·dry-run으로 진행할 수 있다. 새 결정은 근거·대안·영향을 이 문서와 관련 명세 PR에 기록한다.
