# 실제 PR 제출과 사람 평가

구현 결과를 실제 GitHub PR로 제출하고 사람이 평가하는 단계다. Codex 자동 구현 worker는 아직 없으므로 **실제 커밋을 이미 푸시한 동일 저장소의 구현 브랜치**를 입력한다. 모의 실행 완료가 코드 생성·테스트 완료를 뜻하지 않는다. Codex 로그인 차단과 독립적으로 이 기능을 개발·검증할 수 있다.

## 사용

1. 서버에 GitHub CLI `gh`를 설치하고 대상 저장소 읽기·PR 생성 권한의 인증을 준비한다. 현재 클라우드의 플랫폼 GitHub proxy도 CLI 읽기에 사용 가능하다. 토큰을 UI·DB·추적 파일에 저장하지 않는다.
2. API를 다음 환경 변수로 시작한다. GitHub 사용은 기본 비활성이다.

```sh
ARKWORK_DEV_AUTH=1 \
ARKWORK_GITHUB_ENABLED=1 \
ARKWORK_GITHUB_REPOSITORIES=yth1209/ArkWork \
npm run dev:api
```

허용 저장소는 쉼표로 구분하며 대소문자를 포함해 서버 설정과 일치해야 한다. 개인 로컬 개발 owner만 제출·평가한다. dev owner 선택은 운영 사용자 인증이 아니므로 API를 공개하지 않는다. 구독 planning과 함께 쓰려면 `ARKWORK_CODEX_ENABLED=1`도 별도로 설정한다.

3. 요구사항 확인·계획 승인·구현 전 결정 후 결과 검토 단계에서 기준 브랜치와 구현 브랜치를 선택해 **실제 브랜치로 PR 생성**을 누른다. 기준 브랜치와 다른 커밋·파일이 없으면 거절한다. fixture 계획 승인으로 GitHub 쓰기 권한을 얻지 않으며 PR 제출 버튼이 별도 쓰기 요청이다.
4. PR 링크와 전체 변경 파일 링크를 열어 완료 조건을 검토한다. 화면은 변경 파일 최대 100개, 현재 커밋 SHA, CI 집계와 마지막 확인 시각을 제공한다. 전체 파일은 GitHub에서 확인한다.
5. **수정 요청 · 검토 유지**로 사유를 남긴다. 의견은 작업 feedback과 커밋별 이력에 저장한다. 사람이 브랜치에 수정 커밋을 올린 뒤 **PR·CI 상태 새로 확인**하고 다시 평가한다. 자동 수정 실행은 후속 기능이다.
6. **이 커밋 승인 · 작업 완료**로 사람 평가를 완료한다. 이는 ArkWork 내부 평가이며 GitHub Review 승인·댓글 게시·병합을 수행하지 않는다. 배포나 main 변경도 없다. PR 연결 후에는 기존 모의 결과 승인 경로로 우회 완료할 수 없다.

## 승인과 복구 계약

- 평가에는 work version·PR head SHA·10~2,000자 사유·요청 키가 필요하다. 서버는 제출마다 GitHub에서 다시 읽고 다른 커밋·닫힌 PR·초안·실패 또는 진행 중 CI에 대한 승인을 차단한다. 검사가 없으면 **보고된 검사 없음**으로 표시하며 사람이 검증 근거를 판단한다. 통과는 보고된 checks/status 집계이지 branch protection 충족 보증이 아니다. check runs가 100개를 초과해 전체 확인하지 못하면 진행 중으로 취급한다.
- 저장된 승인은 특정 SHA에 대한 기록이다. 웹훅은 아직 없으므로 PR 업데이트를 자동 감지하지 않는다. 새로 확인할 때 head·공개 상태·CI 조건이 바뀌면 승인을 해제하고 완료 작업도 검토 대기로 되돌린다. 원격 확인 이후 발생하는 GitHub 변경과 DB 기록은 원자적이지 않다. 실제 병합 판단은 GitHub에서 최신 상태와 보호 규칙을 확인한다.
- 평가 재전송은 요청 키로 중복 기록을 방지한다. 수정 의견과 이전 커밋의 평가 이력은 보존한다. 자동으로 Skill을 변경하거나 재실행하지 않는다.
- 생성 전에 DB에 저장소·브랜치 제출 예약을 기록한다. 원격 실패가 불명확하면 예약을 유지해 같은 입력으로 재시도한다. work ID marker가 있는 열린 PR을 찾아 재사용하고 GitHub의 동일 head/base PR 제약으로 생성 경합을 복구한다. 닫힌 PR의 자동 재생성은 지원하지 않는다.
- 실제 변경 없음·다른 작업의 기존 PR처럼 확실히 생성하지 않은 실패는 예약을 해제한다. 다른 작업의 PR을 임의로 연결하지 않는다. GitHub가 생성된 PR을 반환한 뒤 연결 완료 전에 닫히는 경우 등 운영 복구는 추가 작업이 필요하다.
- 인증·비허용 저장소·다른 workspace·오래된 버전은 서버에서 차단한다. 현재 adapter는 GitHub App·조직 RBAC·webhook·운영용 배포를 대신하지 않는다.
- migration 005는 PR snapshot을 work item에 저장하며 기존 기록을 유지한다. 서버 재시작 후 제출 예약·PR·평가 이력을 다시 조회할 수 있다. 원본 migration은 수정하지 않는다.

## 검증

`npm test`는 GitHub API transport/Provider 대역으로 생성·재사용·빈 브랜치 거절·권한·커밋 변경·CI·재시도·평가 기록·HTTP 계약을 검사한다. `CHROMIUM_PATH=/usr/bin/chromium npm run test:pr-smoke`는 격리된 서버에서 데스크톱·모바일의 생성 → 수정 요청 → 새 커밋 확인 → 승인 → 새로고침 후 기록 조회를 검증한다. 대역 PR은 실제 GitHub에 게시하지 않는다.

실제 GitHub 읽기는 기존 ArkWork PR #4에서 확인했다(변경 파일 22개, 보고된 CI 통과, 병합으로 닫힌 상태). 사용자 브랜치를 대신 만들거나 테스트용 PR을 GitHub에 게시하지 않는다. 실제 PR 생성·실제 사용자 평가는 대상 구현 브랜치 제출 후 검증해야 한다. 자동 Codex 구현 → 자동 PR 제출까지의 전체 실행은 아직 미구현이다.
