# ArkWork

요구사항에서 소프트웨어 결과까지 이어지는 Software Factory.

현재는 요구사항 확인·사람 승인·모의 진행·결과 검토와 로컬 개발 API를 제공합니다. Codex 구독으로 질문·명세를 작성하는 연결 코드를 추가했습니다. 별도 로그인이 필요하며 실제 코드 생성·저장소 수정·PR 생성은 아직 연결하지 않았습니다.

## 개발

Node.js 24 이상에서 실행합니다.

```sh
npm ci
npm run dev -- --host 0.0.0.0
```

검증: `npm run check`, `npm test`, `npm run build`.

## 서버 모의 실행

별도 터미널에서 다음 명령으로 API를 실행하고, 웹 화면 상단의 **서버 모의 실행**을 선택합니다.

```sh
ARKWORK_DEV_AUTH=1 npm run dev:api
```

API는 127.0.0.1:3001에 연결되고 Vite가 `/v1` 요청을 프록시합니다. 기본 UI 출처는 `http://localhost:5173`이며 다른 포트는 API 실행 시 `ARKWORK_UI_ORIGIN`으로 지정합니다. Vite 프록시는 API 포트 3001을 대상으로 합니다.

서버 모드의 새 작업은 요구사항 확인 질문에 답한 뒤 **실행 계획**을 확인하고 확인란을 선택해 **계획 승인 후 모의 실행**을 눌러야 진행됩니다. 승인 전에는 큐나 worker가 작업을 실행하지 않습니다. 승인에는 요구사항·계획 hash·정책 버전이 연결됩니다. 한 workspace에서 한 건씩 실행하고, 큐·실행 중·사용자 결정 대기 작업은 합쳐 3건까지 승인할 수 있습니다.

실행 중 취소는 먼저 **중단 확인 중**으로 표시되며 worker가 확인한 뒤 취소됩니다. worker의 lease는 5초이며 서버 재시작 직후에는 기존 lease가 만료된 뒤 복구합니다. 자동 실행 시도는 최대 2회이며 반복적으로 권한이 만료되면 실패 상태와 이유를 표시합니다. 이는 서버 모의 진행의 제한이며 유료 AI 실행 승인이 아닙니다.

기존 DB는 새 migration으로 업그레이드합니다. migration 002는 완료·취소 기록을 유지하고 기존 미완료 작업에 계획 승인을 요구합니다. migration 003은 이전 작업의 진행 방식을 보존하며 새 작업에 단계별 사람 개입 흐름을 적용합니다. 서버를 중지한 후 업데이트하고 다시 시작하세요. 적용된 migration 파일은 수정하지 않고 새 파일을 추가합니다.

기본 DB는 PGlite(PostgreSQL 엔진)이며 `.runtime/database`에 저장됩니다. 서버를 종료했다 재실행해도 기록이 유지됩니다. 디렉터리 잠금으로 같은 DB의 중복 실행을 막습니다. 비정상 종료 직후에는 잠금 만료까지 기다린 뒤 다시 시작하며 잠금 파일을 무조건 삭제하지 마세요. `.runtime`는 Git에 포함하지 않습니다. 서버 모드 기록은 서버에 남고 최근 100개를 표시합니다. 로컬 데모 기록과 합치지 않습니다.

`DATABASE_URL`을 설정하면 `pg`를 통한 외부 PostgreSQL 연결을 선택할 수 있습니다. 현재 통합 검증은 PGlite에서 수행했습니다. 외부 PostgreSQL과 다중 worker 운영은 아직 검증하지 않았습니다. 자격 증명이 포함된 URL은 파일·로그·채팅에 노출하지 마세요.

이 API는 **로컬 개발 전용**입니다. 개발용 `owner`/`guest` 계정 선택은 실제 사용자 신원을 증명하지 않습니다. 운영 로그인과 외부 공개 배포에 사용하면 안 됩니다. 명시적 활성화가 없으면 시작하지 않고, 세션·요청 보호 헤더·출처·작업별 workspace 접근을 확인합니다. GitHub 인증은 M2의 후속 작업입니다.

브라우저 검증: 개발 서버 실행 후 `npx playwright install chromium`으로 브라우저를 준비하고 `npm run test:smoke`를 실행합니다. 시스템 Chromium이 있다면 `CHROMIUM_PATH=/usr/bin/chromium npm run test:smoke`로 실행할 수 있습니다. 다른 포트는 `APP_URL`로 지정합니다. 데스크톱과 모바일에서 입력 검증, 진행·취소, 다운로드, 기록 복원과 가로 넘침을 검사합니다.

API와 개발 서버를 모두 실행한 뒤 `CHROMIUM_PATH=/usr/bin/chromium npm run test:api-smoke`로 서버 저장·취소·진행·SSE 재연결 위치·다른 브라우저 조회를 검사합니다. 이 검사는 개발 계정에 모의 작업을 생성합니다. 전체 자동 테스트는 외부 자격 증명 없이 격리된 메모리·임시 DB에서 실행됩니다.

로컬 데모 기록은 이 브라우저에만 저장되며 최근 20개까지 유지됩니다. 두 모드 모두 실제 AI 실행과 코드 생성은 수행하지 않습니다. 민감한 정보나 자격 증명을 요구사항에 넣지 마세요.

작업은 검증 후 main에 직접 커밋·push합니다. 주요 결정은 `docs/architecture.md`, 개발 규칙은 `AGENTS.md`에 기록합니다.

## Codex 구독 연결

ChatGPT 계정으로 `npm run codex:login`을 실행한 뒤 API를 `ARKWORK_DEV_AUTH=1 ARKWORK_CODEX_ENABLED=1 npm run dev:api`로 시작합니다. 새 작업에서 **구독 사용 · Codex 질문 작성** 또는 **구독 사용 · Codex 명세 작성**을 눌러 실제 호출을 요청합니다. 로그인과 버튼 요청이 없으면 호출하지 않습니다. 실제 계정 호출은 아직 검증 전이며 기존 구현 진행은 모의입니다.

[구독 로그인·호출·취소·검증 안내](docs/codex-subscription.md)

## 사람이 결정하고 작업을 재개하는 흐름

기본 화면은 서버 모의 실행입니다. 새 작업은 요구사항 질문에 답변받고, 계획 승인을 받은 뒤 실행하며, 구현 전에 사용자 결정 요청으로 멈춥니다. 결과도 사용자가 승인해야 완료됩니다. 계획·결정·결과에 수정 의견을 주면 입력이 저장된 새 계획을 다시 승인해야 진행됩니다. 응답과 결정 이력은 서버와 다운로드 요약에 보존합니다.

기본 질문과 결정 요청은 데모 항목입니다. 별도 구독 연결로 Codex가 작성한 질문·명세를 선택할 수 있습니다. 실제 코드 수정은 수행하지 않습니다. 자세한 상태·권한·복구 계약은 [사람 개입 흐름](docs/human-checkpoints.md)을 참고하세요. 이전 작업과 로컬 자동 진행 데모는 기존 방식을 유지합니다.

요구사항 입력 → 질문 답변 → 계획 승인 → 실행 중 결정 → 결과 수정 요청 → 재승인 → 결과 승인 → 기록 재조회를 실제 브라우저에서 녹화했습니다. 실제 AI 호출·코드 생성이 없는 서버 모의 실행입니다. 녹화 재현 방법은 [데모 안내](docs/demo/README.md)를 참고하세요.
